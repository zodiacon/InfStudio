# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

INF Studio is a native Windows (C++20, WTL) GUI for viewing and editing driver installation (INF) files. It shows the INF text in a Scintilla editor next to a tree that breaks down its sections (Version, Manufacturer/Models, AddReg, CopyFiles, ...). Its UI follows the author's other WTL tools (e.g. AstroStudio), all built on the shared `WTLHelper` library.

## Build

Visual Studio solution (`InfStudio.sln`), toolset v145 (VS 18: `C:\Program Files\Microsoft Visual Studio\18\Enterprise\MSBuild\Current\Bin\amd64\MSBuild.exe`), `stdcpp20`, static CRT (`/MT`, `/MTd`) everywhere:

```
msbuild InfStudio.sln /p:Configuration=Debug /p:Platform=x64 /m
msbuild InfStudio.sln /p:Configuration=Release /p:Platform=x64 /m
```

- x64 is the platform that matters; the solution's ARM64 maps to x64.
- Dependencies come from vcpkg's user-wide integration (no manifest in the repo). `InfStudio.vcxproj` sets `VcpkgUseStatic`, so it takes the `x64-windows-static` triplet: `scintilla`, `lexilla` (both only installed static), plus `detours` and `wil` that WTLHelper uses. Static Scintilla needs `imm32` (linked by a `#pragma comment` in `InfStudio.cpp`).
- WTL comes from the headers vendored in `WTLHelper\WTL` (on the include path). Nothing uses NuGet anymore.
- `WTLHelper` is a git submodule (`git submodule update --init`). It is the author's shared library with its own repo and its own `CLAUDE.md`, so changes there are a commit inside the submodule and affect other apps.
- `DumpInf` is a console app that prints an INF's version info and sections through `InfCore` (no argument: the master INF). The GUI accepts INF paths on its command line, which makes it easy to launch on a file.

### Tests

`InfStudio.Tests` is a Catch2 v3 console project (x64, Debug and Release). Catch2 comes from vcpkg's static triplet with auto-linking off, so the project lists the libraries it links (Catch2 and Lexilla). It compiles `InfLexer.cpp` and `TextFile.cpp` from `InfStudio/` directly and links `InfCore`. Build the solution, then run:

```
x64\Debug\InfStudio.Tests.exe              # all tests; exit code 0 when everything passes
x64\Debug\InfStudio.Tests.exe [lexer]      # by tag: [lexer], [scintilla], [textfile], [inffile]
x64\Debug\InfStudio.Tests.exe "Strings"    # one test case by name
```

- `InfLexerTests.cpp` checks `InfLexer::StyleLine` with one letter per byte (`.` default, `c` comment, `S` section, `k` key, `o` operator, `s` string, `t` string key, `n` number), so an expected value lines up under its line. The `[scintilla]` tests run the real lexer (`InfLexer::Create`) over a `FakeDocument` (an `IDocument` on a string). They cover what only the Scintilla side does: line ends, the continuation in the line state, lexing from the middle of a document.
- `TextFileTests.cpp` and `InfFileTests.cpp` work on files in the temporary directory (`TempFile` in `TestCommon.h`). `InfFile` is tested through the real SetupAPI. Expectations that depend on the ANSI code page run only under code page 1252.
- `InfTemplatesTests.cpp` generates every template and checks it: placeholders filled, CRLF, ASCII, SetupAPI opens it, every `%strkey%` it uses (found with the lexer) is in `[Strings]`, and the Manufacturer's models sections exist. The `[infverif]` test runs the WDK's `infverif.exe /w` (Windows Driver requirements) on each and is skipped when the WDK isn't installed. A new or changed template must pass it.
- Keep the test sources ASCII (use `\u` escapes): they have no BOM, so MSVC reads them in the ANSI code page.

## Architecture

Projects in the solution:

- **InfCore** (static lib): `InfFile` wraps the SetupAPI INF parser (`SetupOpenInfFile`, `SetupFindFirstLine`, `SetupEnumInfSections`, ...). All INF parsing goes through SetupAPI; there is no custom parser, so a parse error is only a SetupAPI error line number.
- **InfStudio** (GUI exe): depends on InfCore and WTLHelper, and on Scintilla/Lexilla from vcpkg (`<scintilla/...>`, `<lexilla/...>` in `pch.h`). Lexilla's own lexers aren't used: the stock "props" lexer doesn't know INF syntax.
- **DumpInf** (console exe): depends on InfCore.

How the GUI is put together:

- `wWinMain` (`InfStudio.cpp`) loads `AppSettings` from the registry (`AppSettings::RegistryKey`, HKCU) before any window exists, starts dark mode (`WTLHelper::InitDarkMode`: the saved choice, or the system's while `DarkMode` is -1), registers Scintilla's window classes, and restores the main window's saved placement. `CMainFrame::OnDestroy` saves the settings.
- `CMainFrame` (`MainFrm.*`) is the frame: rebar tool bar (`ToolbarHelper`), status bar, and a `CNativeCustomTabView` with one `CMainView` per file. Each page's data is the view's `IView*` (`ViewOfPage`); closing a tab, Close All and closing the app ask each view's `CanClose`. Views reach the frame only through `IMainFrame` (`Interfaces.h`). Menu icons are set with `WTLHelper::InitMenu`, again after a mode switch and for every context menu (`TrackPopupMenu`), since the bitmaps are drawn for the current background.
- Per-monitor DPI (`DpiAware.manifest`, PerMonitorV2, as AstroStudio): `CMainFrame::OnDpiChanged` takes the size Windows suggests and redoes the menu icons, the tabs' icon and the status bar's font and parts (`ApplyDpi`); the tool bar's images and its rebar band after the tool bar has handled the change (`OnDpiChangedPosted`). `CMainView` is a `CDpiAware` (`DpiAware.h`, from AstroStudio: it posts itself a message on `WM_DPICHANGED_AFTERPARENT`, so it runs after its children have handled it) and redoes the tree's and the results' font and icons and the editor's margins; Scintilla scales its own fonts, and `ListViewHelper::EnableColumnDpiScaling` the results' columns. Sizes in the code are at 96 DPI and go through `DpiHelper::Scale`. This machine's monitors are at 96 and 120 DPI: moving the window from one to the other is a real test.
- Read-only files: `TextFile::ShouldOpenReadOnly` (under the Windows folder, as `%windir%\INF` and the driver store are, even for an administrator; marked read-only; or not writable) decides it when a file opens and after Save As; the editor is `SCI_SETREADONLY`, Save is off (and `OnSave` refuses Ctrl+S, which comes even then), the status bar says Read-only, and File > Read Only turns it off or on.
- Files changed on disk: a view keeps its file's `FileStamp` (last write and size: `TextFile::Stamp`) from opening and saving, and compares it when the app is active again (`WM_ACTIVATEAPP` in the frame, `IView::CheckFileChanged`) or the tab is: an unmodified file is reloaded (caret line and scroll kept), a modified one asks first (a No isn't asked again for that change), a file that's gone is told of in the status bar. The check is posted (`CheckFileMessage`), not done while activation is being handled.
- The status bar's panes (`CMainFrame::StatusPane`, `IMainFrame::SetStatusText`'s index): the messages (stretched), then a file's encoding, "Modified", the checks' problems, and Line/Col; widths at 96 DPI scaled in `ApplyDpi`.
- Settings that follow a window's state are saved when they change, not in `OnDestroy`: by then the frame is hidden, and `IsWindowVisible` of its children is false (the status bar was saved hidden on every exit that way).
- Dark mode: Options > Dark Mode calls `WTLHelper::SwitchToMode`, which themes the standard controls and sends the registered `WTLHelper::ThemeChangedMessage` to every descendant. Scintilla draws itself, so `CInfView` handles that message and re-applies its own light/dark palette and scroll-bar theme (`ApplyColors`). A window that paints itself needs the same. Wrap common dialogs (file open/save) in `WTLHelper::SuspendHook`/`ResumeHook`.
- `CViewBase<T>` (`ViewBase.h`) is the base for tab views: a `CFrameWindowImpl` child that deletes itself in `OnFinalMessage`, forwards `WM_FORWARDMSG` to `PreTranslateMessage` and calls `T::OnActivated` when its tab is activated. Commands the frame doesn't handle itself go to the active page.
- `CMainView` holds a splitter with a tree (`CTreeViewHelper`) on the left and, on the right, a horizontal splitter (`m_EditSplitter`) with a `CInfView` (Scintilla via `ScintillaCtrl.h`) above the InfVerif results list (`m_Results`, hidden until the first validation). `ScintillaCtrl.h` wraps only what the app uses (the declarations it once had without bodies are gone): call `Execute(SCI_...)` for anything else, or add a method with its body. `BuildTree` fills the tree from `AnalyzeInf` (InfCore's `InfAnalysis.*`, which returns the tree's structure and is tested) of the editor's text, saved or not: a copy in a temporary file (`WriteTempCopy`, which Validate uses too) opened with `InfFile`. It runs again half a second after an edit (`SCN_MODIFIED`, `AnalysisTimer`) while Options > Live Analysis is on (`AppSettings::LiveAnalysis`, the default; off, after a Save instead), and on Refresh (which no longer saves), and keeps what was expanded and selected by the items' texts (`TreeState`). A models section's install sections come from `InfFile::GetInstallDirectives`, which looks at every platform decoration Windows chooses from (`X`, `X.NT`, `X.NTamd64`, `X.NTarm64`...) and each one's `.HW` section. Each tree item stores a `NodeType`, and its icon is a `TreeIconIndex`, so a new kind of known section means adding to both enums and the image list.
- Navigation (`InfNavigation.*`, pure functions over the editor's UTF-8 text, using the lexer): `FindDefinition` takes a `%strkey%` to its line in `[Strings]` (else a localized `[Strings.xxxx]`) and a section name in a value or key to its `[header]`; F12 and Ctrl+click (`CInfView::SetCtrlClickHandler`; a Ctrl+click that goes nowhere is Scintilla's, which adds a selection) go there, Alt+Left back (`m_BackPositions`). Hovering a string key (`SCN_DWELLSTART`) shows `StringValueAt` in a call tip. The tree's selection follows the caret's section (`FollowCaret`, which reads the section headers by the lexer's style in the editor, not by copying the text).
- Built-in checks (`InfChecks.*`, pure and tested, also against the templates, which must have none): `%keys%` not in a `[Strings]` (numbers are DIRIDs), models and install sections missing (errors), sections a directive names missing (warnings: an included INF may have them; `Needs` names another INF's and isn't checked), files to copy not in a `[SourceDisksFiles]` (errors; a name given by `%key%` is skipped). `CMainView::RunChecks` runs them with the tree's analysis: squiggles under the exact text (`CInfView::ShowCheckProblems`, indicators 10 and 11; InfVerif's are 8 and 9, a line each), the message when hovered, the count in the status bar. Against Windows' 791 INFs they flag 89, mostly library INFs (included by others) and security templates.
- `InfLines::InfModel` (`InfLines.*`) is the reading of a file that the checks and auto-complete share: the styled lines, each line's section, the sections, the string keys, the files of `[SourceDisksFiles]`, every reference to a section (where, and of what kind: models, install, service, WDF service, list), and a section's kind (`KindOf`).
- Auto-complete (`InfCompletion.*`, pure and tested; Scintilla's list): `Complete(text, caret)` gives the word's start, the items and a suffix: string keys after a `%` that opens one (then `%`), sections referenced but missing and standard ones after a line's `[` (then `]`), a key at a line's start by its section's kind (`[Version]`, install sections a device uses or `DefaultInstall` and their `.HW`/`.Services`/`.Wdf`, service sections `AddService` names, WDF service sections, `[DestinationDirs]`: the file sections; then ` = `), and the list sections for a value that names them (`CopyFiles`, `AddReg`, `Needs`..., `AddService`'s third field, `KmdfService`'s second). `CMainView` shows it on `%`, `[` and a word's first letter (`SCN_CHARADDED`) and on Ctrl+Space, adds the suffix after a pick (`SCN_AUTOCCOMPLETED`), and offers the value after ` = `. `InfLines.*` has the styled lines and their keys and fields that it and `InfNavigation` read.
- File > Browse Installed Drivers (`CDriversView`, `DriversView.*`; one tab, activated again if open): `InstalledDrivers` (InfCore's `InstalledDrivers.*`, tested, partly against the real `%windir%\INF`) reads every INF of a folder with SetupAPI (provider and class with strings replaced, `DriverVer` as an ISO date and a version, a third party's `oemNN.inf` with its original name and its driver store folder: `SetupGetInfDriverStoreLocation`, `InfFile::GetOriginalFileName`). The view reads them on a `std::jthread` (progress and the result posted to it; stopped and joined when the tab goes), and shows them in a virtual list (`LVS_OWNERDATA`) filtered, third-party only unless 'Show inbox drivers', sorted by a column (`StrCmpLogicalW`; versions number by number). The devices each package is for come from `InstalledDrivers::DevicesByInf` (every device Windows knows, connected or not, by its `DEVPKEY_Device_DriverInfPath`, the package's published name; read on the same thread): a Devices column (connected, and all in parentheses), the selected package's devices in a pane under the list (a `CCustomHorSplitterWindow`), and the filter matches their names and instance IDs. Enter or a double-click opens the INF (`IMainFrame::OpenFile`); its context menu (right-click, or the menu key / Shift+F10 from `WM_CONTEXTMENU`'s -1 position) opens the INF or its driver store copy, shows either in Explorer (`SHOpenFolderAndSelectItems`) or copies the row or the path. It's shown through `IMainFrame::TrackPopupMenu`, so the command comes back to the tab like the frame's others. (A menu can't be captured with `PrintWindow`: copy it from the screen.) It paints its own background and `WM_CTLCOLORSTATIC` in dark mode (the window class's background is the light one). A tab that isn't a file's disables the file commands in `OnActivated`; `CMainView::OnActivated` enables them again.
- Options > Font: kept in `AppSettings::Font` as a LOGFONT whose `lfHeight` is the size in tenths of a point (`EditorFont.h`, as AstroStudio does); the frame tells each view (`IView::FontChanged`) and `CInfView::ApplyColors` applies it.
- Syntax highlighting is the app's own lexer, `InfLexer` (`InfLexer.*`): `InfLexer::StyleLine` styles one line (no window needed), and a Lexilla `LexerModule` (`InfLexer::Create`) runs it over whole lines, keeping in each line's state whether the line ends with a `\` continuation (the next line then has no key). It also sets the fold levels: a section's header line is a fold header, the lines after it are in it (margin 1 of `CInfView` shows them). Its styles (`InfLexer::Style`) are what `CInfView::ApplyColors` colors; a new style needs a color in both palettes there. A `;` is a comment only outside quotes, `""` is a quote in a string, `%%` a literal percent.
- Text encoding: the editor's document is always UTF-8 (`SCI_SETCODEPAGE`). File > Encoding (ANSI, UTF-8, UTF-16) sets what the file is saved as; a change is unsaved (`m_Unsaved`) until the next save, and the status bar shows it. `TextFile` (`TextFile.*`) loads a file as UTF-8 and saves it back in its own encoding, through a temporary file next to it that then takes its place (`ReplaceFile`, which keeps the file's attributes and security; a new file is moved there): a save that fails leaves the file as it was (`TextEncoding`: ANSI without a BOM, UTF-8 or UTF-16 LE with one); `CMainView::ConfirmEncoding` asks to switch an ANSI file to UTF-16 when it has characters the ANSI code page lacks. Text sent to Scintilla (find, section lookup) must be UTF-8 (`TextFile::ToUtf8`), never `CStringA`.
- Find and Replace: `EditorSearch` (`EditorSearch.*`) searches the editor from the selection, wraps around once and selects the match (F3 / Shift+F3 repeat the last search down or up), and Replace All is one undo action. `CMainView` keeps the last search (`m_SearchText`, `m_Search`). `CMainFrame::PreTranslateMessage` gives keys for another top-level window (the modeless Find dialog) to it before the frame's accelerators, which would otherwise turn Ctrl+V in its text box into Paste in the editor.
- INF > Validate (F7, `/w`) and Validate for WHQL (`/h`): `InfVerif` (`InfVerif.*`) finds the newest WDK's `infverif.exe`, runs it without a console window and parses its `ERROR(code) in path, line N: text` lines. `CMainView::Validate` writes the editor's text (saved or not) to a temporary file of the same name and runs InfVerif on a `std::jthread` (`m_Validator`); the result comes back in `ValidatedMessage`, and `ShowResults` fills the list and squiggles the lines (`CInfView::ShowProblems`). Validating again or closing the tab stops a run still going (`InfVerif::Run`'s stop token kills the process); results of a run that isn't the latest (`m_ValidationGeneration`) are dropped, and an edit after (or during) a run adds a row first saying they're out of date. The messages name the temporary copy: `OnValidated` puts the file's name there. Each purpose has its own temporary folder (`WriteTempCopy(purpose)`: `analysis`, `validation-N`), so the analysis deleting its copy can't take InfVerif's. Enter or a double-click on a problem goes to its line.
- File > New from Template: the templates are data in `InfTemplates.cpp` (`InfTemplates::All()`; text with `@DATE@` and `@GUID@` placeholders that `Generate` fills with today's date and a new GUID). `CMainFrame::AddTemplatesMenu` builds the submenu from that list at startup (command IDs from `ID_TEMPLATE_FIRST`, a separator between `Group`s), so adding a template is adding an entry. They target Windows 10 1709 (`10.0...16299`; UMDF from the driver store needs 1803, `10.0...17134`) on amd64 and arm64, and copy their files to `DIRID 13`. `CMainView::NewFromText` opens the text as a new file: it has no path and counts as unsaved (`m_Unsaved`, part of `IsDirty`) until Save As writes it, since the editor's own modified flag is clear after `EmptyUndoBuffer`.
- `AppSettings` uses WTLHelper's `Settings` macros. A new setting needs both its `SETTING` entry and its `DEF_SETTING` accessor.
- Precompiled headers: each project has its own `pch.h`, which every `.cpp` must include first.
